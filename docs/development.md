# Development

This guide covers building the app from source, the checks that gate a commit, and where
code lives. Engineering rules for humans and coding agents are in [AGENTS.md](../AGENTS.md).

## Prerequisites

| Target | Needs |
| --- | --- |
| All | Node.js 20+ and npm, Rust (stable) through rustup |
| iOS | macOS with Xcode; `rustup target add aarch64-apple-ios aarch64-apple-ios-sim` |
| Android | Android SDK and NDK 27 (`ANDROID_HOME`, `ANDROID_NDK_HOME`), `cargo install cargo-ndk`, `rustup target add aarch64-linux-android x86_64-linux-android` |

The app contains a native Rust module, so it needs a **development build**. Expo Go cannot
load it. Expo changes between SDK releases; check the `expo` major in
[package.json](../package.json) against the [Expo documentation](https://docs.expo.dev/)
before changing Expo or React Native APIs, and add packages with `npx expo install`.

## Build and run

```sh
npm install
npm run native:ios        # build the Rust transport for iOS and regenerate bindings
npm run ios               # expo run:ios: dev build on a simulator or device
npm start                 # Metro for an installed dev build

npm run native:android    # Android: build the Rust transport and bindings
npm run android           # expo run:android: dev build on a device or emulator
```

`android/` and `ios/` are generated by Continuous Native Generation and are not committed.
Configure them through [app.json](../app.json) and config plugins. The static Rust libraries
are not committed either, so a release build (for example with EAS) must run
`npm run native:ios` or `npm run native:android` first.

## Checks

```sh
npm run check             # tsc + eslint + jest + cargo test
```

Run it before every commit. CI ([.github/workflows/ci.yml](../.github/workflows/ci.yml)) runs
type checking, lint, and Jest in one job, and `cargo test` plus `cargo clippy -D warnings`
for the transport in another, on every pull request and push to `main`.

Tests against a real desktop are not part of CI because they need a SovraHarness checkout
next to this one; see [Desktop interop tests](../interop/README.md).

## Stack

| Concern | Choice |
| --- | --- |
| App | Expo SDK 58, React Native 0.88 (New Architecture only), React 19.3, React Compiler, TypeScript 6 strict |
| Navigation | Expo Router (typed routes), file-based in `src/app/` |
| State | Zustand stores in `src/state/` |
| Secure storage | `expo-secure-store` (Keychain / Keystore, this device only, no backup) |
| QR scanning | `expo-camera` |
| Transport | Rust turbo module `modules/sovra-remote` (Iroh 1.4.1 QUIC, same version as the desktop) built with [uniffi-bindgen-react-native](https://github.com/jhugman/uniffi-bindgen-react-native) |
| Tests | Jest (`jest-expo`) for the protocol, `cargo test` for the transport, `interop/` against the real desktop |

## Layout

```text
src/app/               screens (Expo Router): pair, scan, remote, settings, deep link
src/components/        Sovra UI primitives and the remote views
src/remote/            protocol: wire types, strict ticket parser, client, chat flow (pure TS, tested)
src/state/             Zustand stores: remote session, preferences, secure storage
src/theme/             Sovra tokens ported from the desktop design system
modules/sovra-remote/  Rust turbo module (Iroh transport only; no protocol decisions)
                       its rust/ crate is also the transport for SovraAndroid
interop/               Rust tests against the real desktop endpoint and runtime
docs/                  guides for this repository
```

The files in `modules/sovra-remote/{src,cpp,android,ios}` and its podspec are generated by
`ubrn`; regenerate them rather than editing by hand.
